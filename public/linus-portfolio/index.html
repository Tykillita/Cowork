01

Origen · Helsinki, 1991

Una nota abre la conversación.

Viñeta 01 · Señal25.08.1991

No era un anuncio de lanzamiento.

En agosto de 1991, Linus Torvalds escribió en comp.os.minix sobre un sistema que estaba desarrollando y pidió comentarios. La escena empieza con una invitación a conversar, no con la leyenda de un producto terminado.

La historia se cuenta con fuentes: separar el mensaje real de la dramatización. Nota editorial
02

El archivo · Linux 0.01

Pequeño, privado, incompleto.

Viñeta 02 · Precisión17.09.1991

Una carga privada, no un estreno público.

Torvalds aclaró después que Linux 0.01 se subió en privado el 17 de septiembre de 1991 y que nunca se anunció públicamente. Por eso, esta página dibuja un archivo que viaja entre personas, no una multitud frente a un escenario.

Viñeta 03 · Primer materialv0.01

Una base para seguir trabajando.

El archivo histórico conserva el árbol temprano y sus notas. Linux 0.01 era limitado y estaba incompleto: un punto de partida técnico, no la obra de una sola persona ya concluida.

“Una versión es una invitación a revisar, probar y construir encima.”

03

Método · comunidad

El código cambia de manos.

Viñeta 04 · Flujo de trabajoPATCH → REVIEW → MERGE

El kernel se mantiene mediante colaboración distribuida.

Quien propone un cambio lo documenta; las personas revisoras y mantenedoras de subsistemas discuten, prueban y encaminan el parche. El flujo real varía según el área, pero el trabajo depende de muchas voces.

04

Herramientas · Git

Cuando el flujo pide otra herramienta.

Viñeta 05 · Caso de estudio2005

Git

En 2005, Torvalds comenzó Git para apoyar el desarrollo distribuido del kernel. El sistema de control de versiones creció alrededor de rapidez, integridad y trabajo local que luego se comparte.

Viñeta 06 · Diseño01 / 03

Cada persona conserva su ritmo.

El trabajo puede prepararse localmente, compararse y revisarse antes de integrarse. El portafolio muestra el flujo como una red de decisiones, no como una línea de autor único.

Viñeta 07 · Principio02 / 03

La herramienta refleja una forma de colaborar.

Cambios pequeños, historial legible y ramas que se encuentran: una infraestructura para que otras personas aporten sin pedir permiso a una única máquina.
